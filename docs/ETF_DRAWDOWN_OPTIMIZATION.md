# ETF 三买主线：10 日调仓与每日回撤控制

仅优化现有 ETF 三买＋市场宽度策略，没有增加另一套选股策略，也没有删除已有未提交研究。

## 固定规则

- 默认 CLI 调仓周期改为 10 个交易日；收盘形成信号，下一交易日开盘执行。
- 默认总仓位预算上限为 40%；市场中性时再乘原有 50% 暴露系数。
- 每个收盘检查净值：控制回撤达到 4%/6%/8%，仓位预算乘数降至 0.75/0.5/0，即正常风险状态下预算上限分别为 30%/20%/0。
- 非调仓日只减仓、不买入；减仓订单因缺价或零成交额未完成时继续检查。实际仓位超过预算 0.5 个百分点时也触发减仓。
- 降仓后至少等待 20 个交易日，仅在计划调仓日且市场宽度达到 risk-on 条件时，乘数恢复 0.25。恢复时重置控制参考高点；用于报告和 10% 硬停检查的全程净值高点永不重置。
- 全程收盘回撤达到 10% 后，停止新买入并尝试清仓，本轮回测不自动恢复。这是事后触发阈值，不是最大损失保证；跳空仍可能超过阈值。

缺失收盘价使用最近有效收盘估值；缺少开盘价、无效开盘价或零成交额不成交。买入同时预留最低和比例佣金，修正现金透支问题。成交记录增加信号日期与减仓原因，结果包含每日现金及风控状态。

## 使用

项目根目录：

```powershell
.\.venv\Scripts\qkquant.exe etf-backtest --start 2024-01-01 --end 2026-07-20
# 同一修复后的执行引擎、不启用仓位上限和回撤控制的对照：
.\.venv\Scripts\qkquant.exe etf-backtest --start 2024-01-01 --end 2026-07-20 --no-risk-control
# 所有10个调仓偏移、基线/风控/成本压力三组固定比较：
.\.venv\Scripts\python.exe scripts\research_etf_drawdown.py
.\.venv\Scripts\python.exe -m pytest tests/test_etf_drawdown.py tests/test_etf_rebalance_schedule.py tests/test_etf_portfolio_backtest.py tests/test_etf_chan.py tests/test_etf_signal.py -q
```

`--start` 仍是数据加载起点，前120个交易日用于预热，实际净值起点见结果。函数 API 的原有默认周期和无风控行为保留，用于兼容历史研究；生产研究 CLI 明确传入10日和风控配置。

## 实测结果

101只股票类ETF，10万元；净值区间2024-07-04至2026-07-20。默认单边滑点0.2%、佣金0.005%、最低0.2元；压力测试滑点0.4%、最低佣金5元。所有结果使用修复后的同一执行引擎。

| 固定首次调仓偏移0 | 累计收益 | 年化收益 | 最大回撤 |
|---|---:|---:|---:|
| 原逻辑10日 | 25.03% | 12.07% | 16.75% |
| 40%上限＋每日回撤控制 | 9.08% | 4.53% | 7.63% |
| 同一风控、更高成本 | 6.45% | 3.24% | 8.33% |

| 遍历10个首次调仓偏移 | 最差最大回撤 | 回撤不超过10%的偏移数 |
|---|---:|---:|
| 原逻辑10日 | 33.35% | 1/10 |
| 仓位上限＋每日回撤控制 | 10.23% | 9/10 |
| 同一风控、更高成本 | 10.72% | 8/10 |

降低风险有效，但牺牲收益，且仍有亏损偏移。不能宣称全部满足10%回撤，更不能宣称稳定盈利。本轮预先固定一个40%仓位方案，没有根据结果进一步扫描参数。收益变化是仓位上限与每日风控的共同效果，未将两者贡献单独归因。

## 范围与限制

- 本次接入的是研究回测；`etf-plan` 尚未接入账户净值历史、持久化风控状态及固定调仓日历，会明确提示，不可把它当作此版本的实盘订单。
- 尚未完整模拟涨跌停、容量、精确复权份额/现金分红及计划中的限价、跳空取消条件；零成交额过滤只是日线可成交性近似。
- 历史仅覆盖部分深市股票ETF，最新完整截面截至2026-07-20；缺黄金和国债ETF历史。候选已被同一历史反复研究，本轮属于样本内回顾，不是样本外验收。
- 本轮修复也会改变无风控基线，尤其零成交额禁止成交可能改变后续整条路径；因此使用新引擎重新计算基线，而非直接沿用旧报告数字。
- 下一步需要补全数据和账户状态输入，再验证真实执行与未参与选择的数据；不应仅为了历史达标继续降低或优化阈值。
